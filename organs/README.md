# organs/ —— 外设

**内核之外的一切判断力都在这里。** 器官可以摘换：装上是一个实现，换下是另一个实现，内核一行不改。

## 为什么这些东西不在内核里

它们**全部**在同一个测试上失败：**它们是纯函数。**

| 外设 | 为什么它不配进内核 |
|---|---|
| 仲裁器（opex + capex） | 输入是状态快照，输出是决策。纯函数。 |
| 上下文合成器 | 挑候选、打分、填预算。纯函数。 |
| **核验器** | 按 `verify.assert` 独立判定 outcome。纯函数。 |
| 记忆 / 索引 | 可重算。丢了能重建。 |
| 技能店 | 文件系统 + 协议。 |
| 算力池注册表 | 一张表。 |
| HTTP 传输 | 进程，不是盘上格式。 |
| 脚本宿主监督 | 超时与熔断策略。 |
| 停滞计数器 stall/repeat/waste | 观测，不是权威。 |

**"纯函数"意味着：同样的输入给同样的输出，不需要唯一权威、不需要原子、不需要每次经过。**
所以它们不需要进内核——这不是妥协，这正是它们该待的地方。

## 一条关键推论

**核验器在外设里，所以内核不管真实性。**

内核只保证**完整性**：记录没被改过、顺序没被换过、链没断过。
它不认识"技能""策略""增益"——**它不可能管真实性，因为它连这些词都不许有。**

（这是本文档对上一条设计的一处修正：早先想写"链管完整性，内核管真实性"。
按"内核必须微小"的约束，后半句必须改掉。）

## 契约不变

外设与内核之间**只有协议**（[../docs/CONTRACT.md](../docs/CONTRACT.md)）。
外设之间不直接调用；它们通过内核的日志与协议交换状态。
**这条是"器官可摘换"的全部保证**——一旦两个外设互相 import，它们就长在一起了。

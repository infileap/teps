# organs/ —— 外设

**内核之外的一切判断力都在这里。** 器官可以摘换：装上是一个实现，换下是另一个实现，内核一行不改。

## 为什么这些东西不在内核里

它们**全部**在同一个测试上失败：**它们是纯函数。**

| 外设 | 为什么它不配进内核 |
|---|---|
| 仲裁器（opex + capex） | 输入是状态快照，输出是决策。纯函数。 |
| 上下文合成器 | 挑候选、打分、填预算。纯函数。 |
| **核验器** | 按 `verify.assert` 独立判定 outcome。纯函数。 |
| 记忆 / 索引 | 可重算。丢了能重建。 |
| 技能店 | 文件系统 + 协议。 |
| 算力池注册表 | 一张表。 |
| HTTP 传输 | 进程，不是盘上格式。 |
| 脚本宿主监督 | 超时与熔断策略。 |
| 停滞计数器 stall/repeat/waste | 观测，不是权威。 |

**"纯函数"意味着：同样的输入给同样的输出，不需要唯一权威、不需要原子、不需要每次经过。**
所以它们不需要进内核——这不是妥协，这正是它们该待的地方。

## 一条关键推论

**核验器在外设里，所以内核不管真实性。**

内核只保证**完整性**：记录没被改过、顺序没被换过、链没断过。
它不认识"技能""策略""增益"——**它不可能管真实性，因为它连这些词都不许有。**

（这是本文档对上一条设计的一处修正：早先想写"链管完整性，内核管真实性"。
按"内核必须微小"的约束，后半句必须改掉。）

## 契约不变

外设与内核之间**只有协议**（[../docs/CONTRACT.md](../docs/CONTRACT.md)）。
外设之间不直接调用；它们通过内核的日志与协议交换状态。
**这条是"器官可摘换"的全部保证**——一旦两个外设互相 import，它们就长在一起了。

### `session/` —— 第一个实现了的器官

`state.go` 是一张 `map[State]map[Event]State` 转移表；`guards.go` 是四个纯计数判据
（停滞 / 循环 / 浪费 / 同策略重试）；`machine.go` 把它们组装成一个值。

**它的"纯"是性质，不是声称**：`clone()` 逐个复制每个 slice，
`TestStepDoesNotAliasTheReceiver` 与 `TestObserveAndRecordAttemptDoNotAliasTheReceiver`
让"不别名"成为一条**会失败**的断言，而不是一句注释。

**穷尽性是手写的——因为 Go 的 `match` 不强制穷尽**（Rust 会，这是当初比较两种语言时
记下的那条差异）。`TestEveryPairIsAccountedFor` 枚举全部 165 个 `(state, event)` 对，
把允许边与一份手写清单逐字对比；`TestEveryStateIsReachable` 用 BFS 抓孤儿状态。
**10 个变异测试**（删边、改阈值、改比较符、改结算方式）全部被抓住。

**它不知道自己在哪运行。** `session/` 不 import `core`、不碰文件、不做 I/O——
所以在 shell 适配器里它是从日志重放出来的，将来在 dsh 适配器里也一样。
**这条是"外设可摘换"的第一个真实样本，不是口号。**


### `arbiter/` —— "系统自己发现"必须是性质，不是声称

契约写的是 `P(success) ~ Beta(α+成功, β+失败)`。**照字面实现是不够的**：那是一个
记忆无界的运行平均，一个 1000 次成功的技能腐烂之后，要差不多那么多次坏调用才会
掉下来。所以后验做成**带指数遗忘的折叠**，衰减因子是**显式参数**——它就是这个
系统的灵敏度/特异度取舍，藏起来就等于没做这个决定。

证据是一条会失败的测试，不是一段说明：

| 断言 | 读数 |
|---|---|
| 30 次成功后让它腐烂 | **17 次失败内被弃用**（界 25），没有人通知过仲裁器 |
| 负对照：去掉遗忘 | 25 次失败后均值还有 **0.8855**（有遗忘是 **0.5992**） |
| 记忆确实有界 | 500 次观测后无遗忘计数 **502**，有遗忘 **50.0** |
| 弃用不是永久 | 后验从 **0.023 恢复到 0.645** |
| 毒化项能翻转决定 | 同一笔节省：**E1 = −2415.00（拒绝）vs E4 = +35.00（固化）** |

**探索项不是可选的。** 永远选当前最优会让每个决定都不可逆——一次坏补丁会永久
杀死一个好技能，因为再也没人调它。这就是为什么上界永远高于均值。

`escalation.go` 还有一条命名上的决定：动作**按价格取名不按层级取名**。
`L0/L1/L2/L3` 那套让"哪个模型、跑在哪、谁付钱"全都答不上来，因为"层级"不指代成本。

### 器官之间不互相 import —— 第二次被验证

`memory`、`composer`、`arbiter` 都只依赖 `core` 与 `evidence`，彼此不认识。
在适配器里它们是**同一条链上各自投影自己的记录**（`rec:"session"` / `"memory"` /
`"execution"`），而不是一个调另一个。**把三个器官接起来的那个决定，留给了调度方。**

### `executor/` —— 判定不是执行者自己的事

`plan.go` 从 manifest 的投影（`Declaration`）算出**要跑什么**：argv、入口、stdin、时限、断言。
它**拒绝**它跑不了或不许跑的声明——比如 `budget.ms` 为 0 的，理由是逐字的
「an execution with no declared deadline is an unbounded one」。

`verify.go` 的 `Judge(asserts []string, obs Observed) Judgement` —— **签名本身就是纪律**：
入参里没有「成功了吗」这个位置，执行者没有地方把它自己的意见放进来。
`Observed` 全是别人产生的事实：退出码、是否被时限杀掉、是否根本没启动、收到多少字节、花了多久。
`verified_by` 恒为 `verify_assert`。

**判不了就说判不了**（`VerdictUnknown`），而 `Outcome()` 对它返回 `false`
⇒ 适配器**不写 resolution**，链上留下一条永远开着的 intent。
那不是失败，那是**诚实的第三态**：写 `failed` 是猜，写 `ok` 是骗。经 curl 成立，逐字：

```
"outcome":"unknown","resolution":null
reason":"cannot be judged: 我大概成功了吧（an assertion must start with a field name…）；
 this attempt is left open on the chain on purpose: an open intent IS the honest third state,
 and writing any of the five outcomes here would be a lie"
```

**证据只由真实执行提升**：`Elevate` 只认 `Verdict==ok` 且声明等级恰为 E0，且**只给 E1**；
落地方式是「同一份 payload 以 `evidence=E1` 重新 Register」→ 新 ref、新 manifest hash、
canary 指针移到新 ref —— **不碰 `Promote` 的 E0 闸门**。自报成功不算证据，它还是 E0。

| 约束 | 断言（都在 `drive.sh` 里） |
|---|---|
| 执行者不许自证 | `★ 执行者自报成功：退出码 0` / `★ 核验器仍判失败：声明里那条没做到` |
| 判不了不写结论 | `★ 判不了就不写 resolution（链上留空）` |
| 证据只能真实提升 | `★ 一次真实的成功执行把证据从 E0 提到 E1` / `★ 自报成功不算证据：它还是 E0` |
| 拒绝是值 | `★ 没有声明预算的执行不许开始（A7）` / `★ 被拒的执行在链上一个字节都没写，预算也一分没花` |

**能力边界是显式的**：只实现 `script`（唯一能 spawn 且 `env.network=false` 的形态）。
`algorithm`（出进程就不是同一次执行）、`code`（ABI 带源码不带二进制）、`llm_api`（要联网）、
`rl_policy`（没有策略运行时，只剩自报）、`human`（人的一步是声称不是可核验执行）
—— 五种**都显式拒绝**，理由各不相同。**说清跑不了什么，比假装都能跑更接近可信。**

**四个变异全被抓住**（把「确凿为假」判成 ok；判不了回落到 ok；预算为 0 也放行；
判不了也硬写 resolution）—— 这四条恰恰是这个组件存在的理由，所以它们有牙这件事是被证明的，
不是被声称的。

### `executor/compose.go` —— 「生」这个字

宗旨说 `万物 = AI × 算力 × Skill`。三分之二的因子里，「生」此前一直没做：
技能是孤立的，十个技能就是十种能力——**那是三生十，不是三生万物**。

组合让结果**本身成为一个技能**，于是它可以再被组合。这是宗旨唯一能被证伪的那一条。

`PlanComposition(Composition) (Graph, *core.Refusal)` 把组合算成一张**执行图**：

| 算子 | 形状 | 落地了吗 |
|---|---|---|
| `serial` | `A;B;C` —— 第一步吃组合输入，之后每步吃上一步的输出 | ✅ 默认链 |
| `parallel` | `A‖B` —— 每个孩子都吃组合输入，孩子之间不交换任何东西 | ✅ 扇出 |
| `select` / `conditional` | 需要一个**运行期**求值的谓词 | ❌ 规划器是纯的，求不了 |
| `retry` | 需要每次尝试一条链记录 | ❌ 一次 invoke 一个 intent，重试会丢尝试 |
| `loop` | 需要在迭代间求值的终止条件 | ❌ 光有界不算条件 |

四种拒绝**理由各不相同**——合成一句「不支持的算子」会让人以为换个算子名就能过。

**接线必须与默认形状逐字相符。** 显式 `Wires` 顺序无关（那是图不是文本），
但一条本执行器不去兑现的线会被**拒绝**而不是忽略：

> 接受一条自己不去兑现的线，就是静默丢数据，
> 而静默丢数据的组合会给出一个**看起来正常的错答案**。

`JudgeComposition([]Judgement) Judgement` 不重新求值任何断言。组合的核验不是
「把孩子的输出拼起来再套一遍断言」，而是「每个孩子各自被独立判定过了，组合怎么读这些判定」。
规则按顺序：

1. 没有孩子 ⇒ `unknown`（没有证据不许默认成功）
2. 任何孩子**确凿**不 ok（failed / timeout / refused）⇒ 组合就是那个，取**第一个**
3. 否则任何孩子 `unknown` ⇒ 组合 `unknown`（**部分判不了，整体就判不了**）
4. 否则全部 ok ⇒ `ok`

**第 2 条优先于第 3 条**：一个孩子失败了，组合就已经确定不 ok，
不需要等另一个判不了的孩子。反过来先报 `unknown`，会把一个**已知的失败藏起来**。

**执行器把 ref 当不透明字符串，从不校验哈希格式。** 哈希格式是技能店的事实，
在这里再写一遍就是同一个事实的第二个定义——本项目已为此付过三次学费。
执行器只要求 ref 非空，因为它**从不把 ref 变成路径**，没有注入面。


### 串行步的标准输入：一个**静默截断**的坑

组合接进适配器时被抓出来的，值得单独记一笔，因为它不报错。

`executor.NewPlan` 会把调用方的输入当 JSON **规范化**一遍（键排序、数字保留字面量）。
这对 API 输入是对的。但串行步的输入**不是 API 输入**，它是**上一步进程的原始 stdout**：

> `json.Decoder` 只读**第一个** JSON 值就停，剩下的当尾随数据忽略。
> 于是 `{"n":1}TAIL` 被规范化成 `{"n":1}`——**尾巴没了，而且没有任何一处报错**。

下游于是拿到一份缺了尾巴的输入，给出一个**看起来正常的错答案**。这正是最难查的那类错。

修法是 `Declaration.Raw`：

| 输入来自 | `Raw` | 行为 |
|---|---|---|
| 调用方（`"in"`） | `false` | 规范化；`Plan.StdinCanonical = true` |
| 上一步的 stdout（`"prev"`） | `true` | **逐字节原样送达**；`Plan.StdinCanonical = false` |

`Plan.StdinCanonical` 是**如实报告**，不是装饰：「输入被重新排版过」和「输入原样送达」
是两件不同的事，下游看到的行为会因此不同，调用者有权知道是哪一种。

这个规则是「**被截断的观测不许用来判假**」在**输入侧**的孪生规则。
输出侧那条说的是「没找到 READY 可能只是后面还有字节没留住」；
输入侧这条说的是「没找到 TAIL 可能只是尾巴在上游就被吃掉了」。

四条测试钉住它，其中一条刻意断言**尾巴确实会消失**——它记的是失效模式本身，
哪天换掉规范化器它会红，那时这条规则就该重写。

**9 个变异全部被抓住**：第一步不吃组合输入 / serial 输出取全部 / parallel 变串联 /
判不了排在确凿失败前面 / 任何接线都接受 / 空组合放行 / 没有孩子判 ok /
反着穿边界放行 / 重复接线不查。

### 组合是递归的 —— 「万物」这个字的下半截

「生」的第一步是**组合**（`executor/compose.go` 把 `Composition` 算成执行图）。
第二步是**递归**：组合的产物本身得是一个技能，否则十个技能还是十种能力。

那一步刚刚落地，靠的是一个很便宜的观察：

> **让组合拿到一个普通的内容地址，它就和任何别的技能没有区别了。**

于是 `kind:"compose"`：组合自己不跑进程，所以它没有解释器、没有载荷、没有自己的断言
（三者都必须**为空**，因为收下没人读的字段就是收下没人核对的主张）。
它有的是 `deps`（闭包）和 `compose`（图）——而 manifest 哈希覆盖这两样，
所以**图变了就是另一个技能**。

`refs` 指向它，`skill.compose{ref: ...}` 跑它，`deps` 装它。
**孩子是组合就展开成它的孩子**（`expandChildren`），递归。

两条边界：

- **只有串行组合能顶替单步。** 并行组合的产物是**集合**不是**流**，把集合压进流
  就是静默丢数据——所以按名字拒绝，不给近似。
- **深度上限 8 是资源账，不是环检测。** 环早已不可能：manifest 装的是孩子的哈希，
  自引用要求自己的哈希先于自己存在。

★ 还有一个副作用值一记：**后验的分组从「形状」变成了「ref」。**
以前两个毫不相干的串行组合共用一个 `compose:serial` 后验；现在每个组合有自己的。
内联（不带 ref）的组合**仍然只能按形状分**——那是它没有身份的代价，写在注释里。

★ 这一节落地时又抓到一次**同一个事实写了两遍**：意图（intent）用了组合的身份，
结论（resolution）却还在用形状名——而后验表**只数结论**。于是「后验按 ref 分组」
根本没发生，只是意图那半边看起来发生了。断言（查聚合视图里有没有那个 ref）把它抓了出来。

> **同一个名字写两遍，就会有一个地方没被改到。**
> 这是本项目第四次付同一笔学费（`check_contract.py` 的来历、`UnknownLicenseRefusal`、
> 组合与 invoke 的 attempt 键后缀、这一次）。

### 形状就是一条链的身份

规划器提出的链**没有自己的 id**，而没有 id 就**没有任何东西把「我们提议的链」与「它变成的技能」连起来**——那正是准确率成为唯一没有数据的因子的原因。

修法不是新增一个 id 字段，是**发现身份已经在那里了**：一条链的形状就是 `(算子, 有序的孩子)`，而组合清单**本来就声明了这两样**。于是

```go
planner.ShapeID(planner.SearchOp, children)  // sha256(op ‖ 0x00 ‖ child ‖ 0x00 …)
```

这个哈希**能从任何已发布的清单重算出来**，所以它是唯一能活过发布的身份，而且不需要第二份拷贝。顺序是形状的一部分（`serial(a,b) ≠ serial(b,a)`），孩子之间必须有分隔符（否则 `["ab","c"]` 与 `["a","bc"]` 会撞）——`drive.sh` 里有一条断言用 `hashlib` 独立重算它，就是为了让「这条链接不靠另存一份身份」成为可执行的。

## pool/ —— 宗旨里唯一零代码的因子

宗旨是 `AI × 算力 × Skill`。技能是 manifest，智能是仲裁器的一张报价表，而**算力此前只是调用方随手填在 `cost` 字段里的一个数**。`pool/` 是它第一次有自己的形状。

### 四条不显然的决定

| 决定 | 为什么 |
|---|---|
| **价格与预算同单位** | 工作是毫秒与 token，所以资源按「每毫秒多少钱 / 每 token 多少钱」计价。用别的单位就是让仲裁器去加两种货币。 |
| **容量是租约，不是计数** | 说「这个资源两个并发」在有人拒绝第三个之前只是一句愿望。拒绝必须**点名持有者**——「池满了」不是可执行的信息，运维拿着它不知道该问谁。 |
| **租约必须过期** | 没有过期，持有者一死就永久漏掉一份容量，池会**无缘无故地变小**，而且没有任何地方记录过这件事。 |
| **免费是一个价格，不是没有价格** | 整个设计的前提是「一千台机器的空闲算力不要钱」。那是对世界的一个断言，所以要写成 `0` 加一条 `note`，而不是留一个缺字段——缺字段读起来像「还没填」。 |

### 一个 cost 只收资源定价的那一维

```go
MS:     0,                          // 资源消耗毫秒，不增加毫秒
Tokens: chargedTokens(r, work),     // 只有按 token 计价的资源才收 token 额度
Money:  int64(ms*r.MoneyPerMS + tok*r.MoneyPerToken),
```

`Cost` 说的是**资源从调用方拿走什么**，不是「这份工作有多大」。这一条是 `tools/drive.sh` 抓出来的：`pool.quote` 对一切都回 `budget_exhausted`，因为免费的本机核也在收调用方根本没打算用掉的 token 额度——**那正好是免费资源存在的反面**。

### 租约记录存绝对过期时间，不存 ttl

服务端在拿到租约的那一刻用**自己的时钟**盖章。存 ttl 会让每次重放都对着不同的「现在」重算，**同一条链描述出不同的池**——而重放必须给出同一个答案，那是这个项目从第一天起就在守的东西。

### 报价回答的是哪个问题

`U = p×value − cost` 里的 `cost` 是哪一种成本？两种都成立，而它们**排序不同**：

| 口径 | 效用 | 含义 |
|---|---|---|
| `attempt`（默认） | `p×value − cost` | 试一次要多少钱 |
| `success` | `p×value − cost/p` | 成功一次要多少钱 |

同一对报价：A（p=0.99，cost=0.9）与 B（p=0.50，cost=0.1），value=1.5
——按 `attempt` B 赢（0.650 > 0.585），按 `success` **A 赢**（0.576 > 0.550）。

**两个数都不是错的。** 一个系统选了哪一个而不说出来，它的选择就不可读。

三条边界：
- `cost` 是**真正进了效用函数**的那个数。报一个没被用上的数，等于让人以为他看懂了那次决定。
- `cost_per_success` **永远**是成功一次的价格，不管这次用的是哪个口径——一个叫这个名字的字段里放一次尝试的价，就是同一个名字下的另一个数。
- `p = 0` 时**没有**每次成功的成本。一个一次也不成功的动作什么都买不到，报一个很大的数会是另一种形状的假话。

### 一个价格只有放在它买到的东西旁边才有意义

花费与成功率各自都有定义，但「每次成功花了多少钱」是**第三个事实**——而它恰恰是唯一能回答「这件事值不值得做」的那个。

`metrics.get` 报 `cost{spent, successes, per_success}`。**分母为零时它没有定义**：一个没有成功的每次成功成本，是一个装扮成数字的除零。

那条断言只能放在 `drive.sh` **最开头**问，因为一旦有东西跑成功过，那个状态就再也回不来了。这也是一条通用规则：**要断言一个状态，得在它还存在的时候问。**

`ok` 与 `spent` 一样，是对同一批记录、**同一次遍历**的计数。一个来自别处的成功计数（调用方的声称、退出码、执行者自己的意见）会是同一个名字下的另一个数。

### 花费落到链上

定价接好之后还剩一处不对：`skill.invoke` 的 resolution 记录里 `cost` 一直是 `0`。准入算了钱、仲裁器取了价，**而链在声称每一次执行都是免费的**——于是「这次执行值不值」永远没有数据。

现在 resolution 带上准入算出的那个数，`arbiter.state` 与 `metrics.get` 都报 `spent`。

两条纪律在这里各出现一次：

- **报一个价不等于付那个价**（上一节的变异漏网教会的）；
- **付了却不记下来同样是一句假话**。

`spent` 与 `observations` 从**同一次遍历**里得出，所以它们不可能漂移——有一条测试专门钉这个不变量，因为这是本项目付过最多次学费的那一类错。

### 报价的钱从池里取

定价之后还有一步：**仲裁器手里的那个 `cost` 是谁填的**。在接入之前，它是调用方在 offer 里手打的一个数——于是整个 `U = P(success)×value − cost − latency` 只是调用方猜想的回声。

`arbiter.rank` 的 offer 现在可以点名一个资源（`resource` + `ms`/`tokens`），钱由 `pool.Cost` 算出来。**同时给 `resource` 和 `cost` 被拒**：一个数不能有两个来源，而它们不一致的时候，谁也不会发现。

**占不到的报价不是更便宜的选择。** 它被排除出排序，但**照样被报出来**并说明原因——静默丢弃的剪枝无法被审查，而「我明明报价了却没被选」是最需要能查的一句话。

★ 这一节也踩了一次「同一个事实两份拷贝」：每条报价的账原先用 `action` 当键，而**两个 offer 可以都是 `skill` 动作** ⇒ 后一个把前一个的账盖掉，而响应看起来完全正常。改用 offer 自己的不透明 `Tag`（`organs/arbiter` 的 `Offer` 增了 `Tag string`，仲裁器从不读它）。

### 准入：池第一次真的决定一次执行能不能跑

定价之后还有一步：**谁来决定这次执行跑在哪**。在接入之前，执行器总是本机 spawn，而「在哪台机器上跑」从来不是一个决定。

`skill.invoke` 现在有两个字段：

| 字段 | 意思 |
|---|---|
| `resource` | 点名一个资源 id |
| `pick` | 让池从**本机**资源里挑最便宜的 |

两个都不给，就是「不点名」——本次执行不受准入约束，响应里 `resource` 是空字符串加一句说明。**不凭空造出一个没人登记过的资源**：那是链上的一句假话，而链是唯一被信任的东西。

三条边界：

- **执行器只认得本机的资源。** 远端 GPU 登记得上，但本组件没有把进程送到另一台机器上去的手段。把 `gpu.far` 记成一次执行发生的地方，就是在链上写一句假话。所以非本机的资源被**明确拒绝**，理由说清是「这个组件做不到」，不是「这个资源不好」。
- **顺序是先占槽、再扣钱、最后 spawn。** 占不到槽的执行不该留下已付费的痕迹——一条被拒绝的尝试在链上看起来像一次付费的尝试，是最难查的那类错。
- **租约的长度由硬时限推出来，不由调用方传进来。** 传进来就能传一个等于时限的值，于是槽会在进程被杀死的那一刻正好过期。那是一个没人会注意到的差一，直到它真的发生。

### 边界

`Live` 判 `Expires <= now` 即过期。这个边界不是细节：聚合的 `used` 与按资源看到的活租约是**同一个事实的两份实现**，而边界正是它们分道扬镳的地方。所以有一条测试专门让两者在 `now` 正好等于过期时间时逐点比对——它是为一条漏网的变异写的。

## planner/ —— 「万物」这个字的后半截

组合执行器让组合**能**被组合；规划器让系统**提议**组合。这是宗旨第 4 条验收的
后半句：**产生未经人手编写的新能力**。

三条不显然的决定：

1. **这是「类型正确」，不是「正确」。** 两个 `text→text` 的技能仍然可能配不上。
   规划器把巨大的空间缩小，好不好要跑一遍由核验器决定，然后进后验。它不假装知道
   语义，只处理它真能处理的那一层。
2. **搜索是精确的，不是启发式。** 前沿按「可达类型集合」去重、保留最可靠的链——
   一条链的续法只取决于可用的类型集合，与怎么到达无关。所以对固定类型集，
   更可靠的前缀支配。被支配的路**被报告出来**，因为有趣的问题通常不是「找到了什么」，
   而是「它拒绝考虑什么」。
3. **技能可以被用两次。** `A;A` 可以合法，所以状态是**类型集合**，不是「用过的技能集合」。

可靠性是**乘积**，所以「偏好短链」不需要谁写一条规则——它是乘积的性质。
`drive.sh` 里能看到地板的两种作用：`0.99²=0.9801` 被提议，`0.99⁹=0.9135` 被拒并附理由
（`a chain of good steps is not a good chain`）。

### 一次协议层的命名冲突

这个 op 最早叫 `compose.build`，而 `organs/composer` **已经**用这个名字建上下文窗口。
**帧类型是全局命名空间**，两个器官都要它。修法不是改名，是发现我那个是多余的：
组合**就是**技能，所以它用 `skill.publish` 发布，不需要第二个发布口。

> 同一个词在同一个系统里指两件事，代价总会有人付——这次是 drive.sh 的七条断言。

## composer/ 的必需材料：把一次静默的失败变成一次显式的拒绝

架构笔记里唯一一条可以直接执行的规则是「**超了就拆，绝不扩窗**」。它值钱的地方不在于
省 token，而在于**它把一个静默的失败变成了一次显式的拒绝**：

> **缺了必需品的上下文不会报错。它会给出一个看起来正常的错答案**，
> 而下游没有任何东西能看出这份上下文是从一份不完整的预算里拼出来的。

所以 `Candidate.Required` 有三个面，缺一个就漏：

| 面 | 不这样做会怎样 |
|---|---|
| `Dedup`：必需的那条不输掉近似重复 | 被丢掉的正是「不可选」的材料，而**活下来的文本读起来很正常** |
| `Pack`：必需的先占位，其余按 score/长度填 | 高分的可选材料会把低分的必需品挤出预算 |
| `Compose`：必需的仍然装不下 ⇒ `budget_exhausted` | 交出一份更小的上下文，而它**答得像对的** |

拒绝必须点名**是谁、在哪一段、那条预算多大**，并说明替代办法是**拆任务而不是扩窗**——
否则调用者只能猜。

负对照也是测试的一部分：**非必需**的材料装不下仍然只是被丢掉。
少了这条，上面三条测的会是「装不下就拒绝」这条更粗的规则。

## reflex/ —— 唯一一层不用上下文的回答

它跑在**任何**上下文被拼出来之前，所以它省下的不是 token，是整条流水线：
composer、retrieval、memory 一个都不参与。这不是一句承诺，是**结构性事实**——
有一条测试直接读 `reflex.go` 的源码，断言它只 import 标准库与 `core`：

> 这一层若 import 了 composer 或 memory，它就不再是反射，
> 而「零上下文」也就从结构性事实变成了一句口号。

**它不是「加了步骤的查找表」。** 三个性质，一个普通 map 一个都没有：

| 性质 | 机制 |
|---|---|
| 建立 | 从 `0.3` 起步，**低于阈值 `0.6`** ⇒ 一次观测永远不够，要看见它成功两次 |
| 可改 | 成功 `+0.2`，失败 `−0.4` |
| 可消退 | 每个空闲周期 `−0.1`，掉到阈值以下就不再回答，**但它还在**——一次成功就能回来 |

**不对称（`WeakenStep 0.4 > ReinforceStep 0.2`）是这一层的核心判断：**

> 漏触发只多走一次完整路径，那条路径仍然是对的；
> 误触发是**在完全没有上下文的情况下自信地答错**。

所以它被刻意调成偏向不触发。

**匹配是精确的，这是刻意的。** 规范化之后必须完全相同才触发。近似匹配是另一种、
且危险得多的东西——这一层的全部价值是便宜，而一次错反射的全部代价是
**自信地答错，且没有上下文可以反驳它**。模糊的键正是「看起来正常的错答案」的来源。

### ★ 一次观测不够回答，是这一层承诺的性质，不是实现细节

`InitialStrength` 一开始是 `0.5`，而 `reflex.observe` **既建立规则又应用结果**——
所以新规则一出生就已经走了一步：`0.5 + 0.2 = 0.7 ≥ 0.6`，第一次成功就回答，
与包文档承诺的「一次观测永远不够」直接矛盾。

**单元测试没抓到**，因为它把错的常量写进了自己的期望
（`TestOneSuccessMakesItFire` 断言的就是「一次成功就触发」）。
`drive.sh` 抓到了——那里的期望是从这一层承诺的性质推出来的，不是从代码里抄的。

> 一条测试如果把自己的常量写进断言，它就抓不到那个常量是错的。

### 它不报拦截率

设计笔记里唯一可证伪的数字是「反射层拦截 60–80%」。**这个数字没有被报，缺席是刻意的**：
率需要分母，分母是「收到的任务」，而这个系统**没有任务入口**。
拿 `reflex.match` 的调用次数当分母会得到一个**看起来像那个断言、实际什么都没测**的数——
和把公式里未定义的因子当成结论是同一个错。

报出来的是表本身：多少条规则、多少条在触发、多少条已消退。那些是**真的发生过的计数**。

## intake/ —— 分母

设计笔记里唯一可证伪的数字是「反射层拦截 60–80%」。这个数字在 `intake/` 之前
**没法测**，不是因为算不出来，而是因为**分母不存在**：

> 这个系统没有「收到的任务」。一个没被记录的到达，在率的意义上就是没发生过。

所以记录到达不是记账，**它是「一句断言」和「一次测量」之间的差别**。

### 它刻意不认识 reflex

`intake` 不 import 任何别的器官。它认识的是**「能用零上下文回答的层」**这个接口：

```go
type Answerer interface {
    Name() string
    Answer(stimulus string) (action string, ok bool)
}
```

路由策略只有一句话：**最便宜的、愿意答的那层来答。**

如果它直接拿 `reflex.Rule` 来用，第二个零上下文层出现时路由就得改——
而「多一个便宜层」恰恰是这一层最该受益的变化。

### 三条不许含糊的规则

| 规则 | 不做会怎样 |
|---|---|
| 没记层的到达**算进分母**，且算成完整路径 | 丢掉它会**靠忘记不顺利的那些来提高率** |
| 各层计数**加起来等于总数** | 否则报告里少掉的那部分正好是没人想看的 |
| 率**永远带着作用域** | 「60–80%」之所以没人能核对，就是因为它没有分母 |

```json
{"total":3,"by_layer":{"full":1,"reflex":2},
 "intercept_rate":0.6667,"scope":"tasks that arrived at this intake"}
```

`Scope` 不是装饰：**一个不带分母的率，就是一个看起来像结论的断言。**

## distill/ —— 把一次成功变成一条候选规则

第四条路径 **L1 → 反射网络**，也是今天唯一不需要模型就能建的一条：
经验已经在链上，产物是一条规则。

### 闭环，逐字可跑

```
一个没见过的刺激  →  落到完整路径（付一次上下文）
                 →  成功，可蒸馏
                 →  蒸馏：建立规则，强度 0.5（阈值之下，**不回答**）
再来一次          →  仍然落下去（一次成功不够）
                 →  再确认一次：0.7
第三次            →  ★★ 反射层答，零上下文
```

**没有任何人写过这条规则。** 拦截率不是被设定的，是被学出来的。

### 只有两种成功可以被蒸馏

| 判据 | 不做会怎样 |
|---|---|
| **只有成功**可以蒸 | 失败教的是**回避**不是规则；蒸了它，系统会自信地重做一件没成的事，而记录会说它被验证过 |
| **只有花了成本的成功**可以蒸 | 已经零上下文答过的东西再蒸一次，就是**把同一次成功数两遍**——强度涨了，而什么都没发生 |

「没人记录过它成没成」也是拒绝，而且**理由里要把它说出来**：

> `only a verified success is distillable, and this outcome is missing (nobody recorded whether it worked)`

### 蒸馏出来的是候选，不是规则

反射层本来就有处理候选的正确机制：**建立，然后确认**。

> 一条蒸出来就立刻回答的规则，正是证据阶梯一直在防的那种毒化：
> 一次成功被直接提升成一条规则。

所以 `distill.apply` 的响应里**明说**这一点：

```json
{"strength":0.5,"fires":false,
 "note":"established, not confirmed: it will answer only after the same stimulus is seen working once more"}
```

### 规则 id 必须由**规范化后**的刺激派生

否则同一个刺激的两种写法各建一行，而反射层是按规范化后的形式匹配的——
**两行都会命中，一次经验的强度被拆成两半。**

规范化属于反射层，所以适配器去问它，而不是把规则抄一遍。适配器是两个器官被允许相遇的地方。

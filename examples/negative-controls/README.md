# 成对的负控

这个目录里是 **4 对**可以离线复跑的负控。每对两半：**必过**与**必败**。

## 为什么要成对

一份只有必过用例的声明，证明的是「它通过了」；**没被证明的是「它有能力失败」**。
于是 `exit == 0` 的技能只要永远返回 `0`，就能拿到 E1——**永远成功和正确地成功，在那份声明下分不出来**。

一条**只在必过那一半成立**的断言不是检查，是形式：它分辨不出任何东西。
所以这里的每一对都同时给出两半，而**两半必须给出不同的判定**。

## 怎么跑

```sh
bash examples/negative-controls/run.sh
```

它只用 `curl` 与 `python3`：现建内核（`tools/go build`）、起一个本地 HTTP 内核、逐对发布与调用、逐对核对判定、关掉内核。没有 SDK、没有语言运行时、没有网络。

形状对不对由 `tools/check_examples.py` 守（它不建内核）。

## 四对分别是什么

| id | 抓住什么 |
|---|---|
| `exit-code-is-not-a-conclusion` | 退出码 0 被当成结论：命令报成功，产物却缺失 |
| `empty-needle` | 空针匹配一切：`stdout contains ""` 在任何输出上都是 true |
| `probe-silent-vs-empty` | 「探针沉默」与「拿到但是空」被折叠成一个结论 |
| `truncated-tail` | 解码器读到一半就停：尾巴没了，没有任何一处报错 |

## ★ 判定里只有一个是「被驳倒」

负控**不是**「换个输入再跑一次看 `outcome`」。它是 `verify_refute` 里的一条声明——
喂这个输入，这条断言**不应该成立**——而引擎把结果放在 `elevation.refutations[]` 的 `held` 与 `verdict` 里。

`failed` 是**唯一**算被驳倒的判定：

- `timeout` 是关于**时间**的事实——它没在预算内回来；
- `refused` 说明**进程根本没起来**；
- `unknown` 是**判不了**。

把三者里的任何一个算作驳倒，就是让一个坏掉的技能靠「跑不起来」拿到双边证据。
所以每条负控自己声明它期望哪一种，并因此说清它在证明什么：期望 `unknown` 的那条，
证明的是**「这条断言判不了」**，那是另一种发现，不是「这条断言被证明为假」。

# store/ —— 技能店

**按包管理器设计，不按目录约定设计。**（完整规格待补；本文档已载其关键决定。）

## 内容哈希是一个三元组，而字符串只是其中一段

算法、版本、归一化——**把其中一段留成隐含的，那一部分就会在没人注意的时候出错**。

具体代价：`Get` 用 sha256 重算并比对，而算法是隐含的。一个别的 64 位十六进制算法产出的摘要**通过形状检查**（64 位小写十六进制），重算不符，于是调用方被告知 `recovery_required`——「这些字节损坏了」。真话是「本店没有实现那个算法」。

> **两个不同的事实，一个码。** 而第二个把读者送去一个不存在损伤的地方找损伤。

修法不是换一种存储格式，而是**让摘要能说出自己的算法**：

| 形式 | 含义 |
|---|---|
| `<64 位十六进制>` | sha256。这是磁盘与线上的形式，改掉它会重写每一个店里每一个 ref |
| `sha256:<hex>` | 同一件事，只是说出来 |

`ValidDigest` 同时报出**算法**与**合法性**，于是「畸形」与「格式对但不是我的」是两个答案。`Get` 与 `Has` 都走它——**一个 `Get` 认、`Has` 不认的店，它的两半对「什么是一个名字」意见不一致**。

第三个腿在 `GetJSON` 里：重算 `core.Canonical` 并比对。字节完好但写在另一套归一化下，是**同一个值在另一个身份下**，而那是与损坏不同的答案。

### ★ 顺着它查出 `Resolve` 把四个事实压成了一句话

`Resolve` 原本对每一个读取失败都回同一句「not a skill_ref in this store」。四个事实因此无法区分：

| 事实 | 该说什么 |
|---|---|
| 不存在 | 你要的东西不在这里 |
| 字节损坏 | `recovery_required` |
| 算法没有 | `bad_request`，并点名那个算法 |
| 归一化不同 | 说清是哪一套归一化 |

只有第一个意味着「不在这里」。**把它们折叠起来，就是把每一个读者都送上同一条路，而其中三条是错的路。**


## 为什么是 Nix 式而不是 npm 式

| | npm 式 | Nix 式（本项目的选择） |
|---|---|---|
| 版本 | 可变，就地升级 | 不可变，内容寻址 |
| 回滚 | 靠运气 | 切指针，秒级 |
| 依赖 | 依赖地狱 | 隔离闭包 |
| 安装脚本 | `postinstall` 可任意执行 | 构建沙箱，无网络 |
| 审计 | 事后追 | 哈希即证据 |

## 两个不显然的决定

**① `skill_ref` 哈希的是「环境闭包」，不是脚本文件。**

抄来的代码绝大多数是 Python，而 `pip` 的依赖闭包**本质不可能内容寻址**。
如果哈希只覆盖那个 `.py`，同一份哈希会在不同机器上跑出不同结果——那哈希就没有意义了。
所以：**把技能关进固定环境，哈希那个环境。**

**② 组合技能的证据等级 = `min(子技能的等级)`。**

组合不许提升证据等级。否则可以把一堆 E1 拼成一个"看起来是 E3"的东西，
**这就是毒化洗白的入口。**

## 组合代数（`store/` 与内核的交界处）

技能不是孤立的，否则 10 个技能只是 10 种能力——**那是三生十，不是三生万物**。

```
串行 A;B    并行 A‖B    条件    循环    重试    选择 A|B
```

组合结果**本身是技能**，进店，可再组合。

★ **可靠性是乘积 `∏P_i`**：10 × 0.99 = 0.90；20 × 0.99 = 0.82。
⇒ **组合搜索必须被可靠性剪枝**，否则会大量生成"看起来能跑、成功率 0.3"的方案。
⇒ `max_depth` 由可靠性预算定：P̄=0.99 且下限 0.9 ⇒ d≤10；P̄=0.95 ⇒ d≤2。

### 三个被实现钉住的细节

**① `skill_ref` 是 package 哈希，不是 manifest 哈希。**
manifest 哈希只覆盖「声明了什么」，是**内部地址**；package 哈希覆盖声明 + 载荷 +
解析出的许可证闭包，那才是技能的**身份**。`deps` 里存的也是 package 哈希。

**② `Package` 里刻意没有时间戳。**
时间戳会让同一技能每次注册都得到不同哈希，去重就没了。时间属于 ref 历史——
**它在内容之外，因为它本来就不该改变内容。**

**③ 先写历史，再移指针。**
反过来（先移指针再写历史）在崩溃时会允许「切换了却没有记录」，回滚就**不可审计**。
现在崩溃只留下「一次没落地的切换」：良性，而且可见。

### ★ 一次被 curl 抓到的代码内漂移

`Manifest.Validate` 对未知许可证返回 `bad_request`，而 `SolveLicense` 对同一事实返回
`license_conflict`。**两道门、一个事实、两个码**——客户端的重试循环会在一条路径上工作、
另一条上不工作。修法是让两边调用**同一个构造点** `UnknownLicenseRefusal`，
并加一条测试钉住「一个事实只有一个码」。

### 与内核的交界：**复用同一套拒绝码**

`store` 直接 `import "teps/core"`，不另造一套码。第二套词汇会与第一套漂移，
而漂移是静默的——本项目已经为此付过一次学费（`tools/check_contract.py` 的来历）。

## `kind:"compose"` —— 组合是一种**结构**，不是执行形态

组合自己不跑进程。它的孩子各自按自己声明的形态跑，**组合的形态是连接它们的图**。
这就是它是六种 kind 里**唯一**既没有解释器、也没有载荷、也没有自己断言的那一种，
而这三点都是**拒绝**而不是忽略：

| 字段 | 组合必须怎样 | 拒绝理由 |
|---|---|---|
| `env.interpreter` | **必须为空** | `declares no interpreter: it runs no process of its own, so this field would never be read` |
| `files` | **必须为空** | `carries no files: its graph is its payload, and these N would be bytes nothing runs` |
| `verify_assert` | **必须为空** | `declares no verify_assert: a composition produces no observation of its own` |
| `deps` | **必须非空**，且**每个孩子都在里面** | `compose child N is not in deps: a composition must declare its closure` |

**为什么 `verify_assert` 是拒绝而不是「随便填」**：收下一个没人读的字段，就是收下一条
没人核对的主张。让它真正有意义要拿组合自己的断言去对**它的最终可观测**（串行时 = 最后一步的
stdout）——那还没实现，所以现在这个字段就是装饰，而装饰不该被接受。

### ★ 内容寻址把无环性**白送了**

manifest 装的是孩子的**包哈希**。一个组合要引用自己，就得让**自己的哈希先于自己确定**——
那是一个不存在的固定点。间接环每一步同理。

**所以 `maxComposeDepth = 8` 是资源账，不是正确性账。** 这条区分写进了那条拒绝理由里，
免得日后有人把它当成环检测，并因此以为改大它就会出环。

### ★ 两个哈希，两个职责（这一节把上一轮的结论用在了组合上）

- **manifest 哈希** = 技能**声明**了什么
- **package 哈希** = 整个**制品**（声明 + 载荷 + 解析出的许可证闭包）= `skill_ref`

refs 指向 package，`deps` 存 package 哈希。组合因此和任何别的技能**一样**：
它有一个内容地址，所以它可以被 ref 引用、可以被当成另一个组合的孩子、可以有自己的后验。

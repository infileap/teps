## 为什么是 Nix 式而不是 npm 式

| | npm 式 | Nix 式（本项目的选择） |
|---|---|---|
| 版本 | 可变，就地升级 | 不可变，内容寻址 |
| 回滚 | 靠运气 | 切指针，秒级 |
| 依赖 | 依赖地狱 | 隔离闭包 |
| 安装脚本 | `postinstall` 可任意执行 | 构建沙箱，无网络 |
| 审计 | 事后追 | 哈希即证据 |

## 两个不显然的决定

**① `skill_ref` 哈希的是「环境闭包」，不是脚本文件。**

抄来的代码绝大多数是 Python，而 `pip` 的依赖闭包**本质不可能内容寻址**。
如果哈希只覆盖那个 `.py`，同一份哈希会在不同机器上跑出不同结果——那哈希就没有意义了。
所以：**把技能关进固定环境，哈希那个环境。**

**② 组合技能的证据等级 = `min(子技能的等级)`。**

组合不许提升证据等级。否则可以把一堆 E1 拼成一个"看起来是 E3"的东西，
**这就是毒化洗白的入口。**

## 组合代数（`store/` 与内核的交界处）

技能不是孤立的，否则 10 个技能只是 10 种能力——**那是三生十，不是三生万物**。

```
串行 A;B    并行 A‖B    条件    循环    重试    选择 A|B
```

组合结果**本身是技能**，进店，可再组合。

★ **可靠性是乘积 `∏P_i`**：10 × 0.99 = 0.90；20 × 0.99 = 0.82。
⇒ **组合搜索必须被可靠性剪枝**，否则会大量生成"看起来能跑、成功率 0.3"的方案。
⇒ `max_depth` 由可靠性预算定：P̄=0.99 且下限 0.9 ⇒ d≤10；P̄=0.95 ⇒ d≤2。

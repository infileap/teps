# adapters/ —— 宿主适配层

**这一层是可删的。** 删掉全部适配器，内核、外设、存储照样跑，只是少了一种入口。

## 铁律：适配器与内核不共享概念，只共享传输

这是最容易犯、代价最大的一类错误：

> 把 DSH 的 session 当成集群的 session。

一旦复用概念，两者就纠缠在一起；将来要脱离宿主时，**必须重写**。
所以适配器是**翻译**，不是**内建**：

```
宿主的概念  ←翻译→  NDJSON 帧  →  内核
```

内核永远不知道对面是 DSH、Claude Code、Codex、MCP 还是裸 curl。

## 适配器按协议命名，不按宿主命名

原计划里有 `adapters/dsh/`。**那个目录不该存在。**

「dsh 适配器」不是一种东西——DSH 消费一个内核的方式是 MCP。所以
`adapters/mcp/` **就是** dsh 适配器，同时也是 Claude Code 适配器、Codex 适配器，
以及任何别的会说 MCP 的东西的适配器。

按宿主命名会让同一份翻译代码被写第二遍，而第二遍必然与第一遍漂移；
按协议命名则让「支持一个新宿主」退化成「宿主自己会不会说这门协议」。

## 两种适配器，两种规则

| | 谁 | 规则 |
|---|---|---|
| **参考传输** | `adapters/shell/` | 它**拥有**内核，所以**必须** `import teps/*` |
| **翻译器** | 其余每个 `adapters/<x>/` | **不许** import 项目的任何包，只能走 NDJSON |

这条规则是结构性的，不是风格偏好。**本项目已经为「第二套词汇」付过三次学费**：

1. 文档的拒绝码表与 `core/refusal.go` 不一致 ⇒ 逼出 `tools/check_contract.py`
2. `Manifest.Validate` 与 `SolveLicense` 对同一个未知许可证给了两个码
3. 适配器允许执行者自证 outcome

一个 import 了内核的适配器不再是适配器，而是**内核的第二个入口**。
第二个入口必然漂移，因为没人会同时改两处。

守卫：`tools/check_adapters.py`（两个方向都查）。参考传输那条写成
「必须真的 import，否则这条规则是平凡的真」——如果参考传输不再拥有内核，
守卫会自己说出来，而不是继续通过。

## 自由判据（可执行，两条）

> **删掉这两个宿主之后，一段 curl / printf 脚本能驱动全流程。**

这条判据不是口号，是**两个可跑的脚本**：

```sh
bash tools/drive.sh       # 103 项：只有 curl，覆盖内核 / 会话 / 技能店 / 记忆 / 合成器 / 仲裁
bash tools/drive_mcp.sh   # 21 项：只有 printf 的 JSON-RPC，覆盖 MCP 翻译器
```

它们跑不通，就说明有东西漏进内核了。

## 翻译器最容易做错的三件事（`drive_mcp.sh` 专门测这三条）

1. **把拒绝压成一句话。** 丢掉 `code` 与 `retryable`，调用者就分不清哪条拒绝能重发、
   哪条不能——而它会重发不能重发的那些。所以内核的原始帧**逐字**交回。
2. **白名单化转发。** 内核会拒绝任何自带 `seq` / `head` 这类服务端字段的帧。
   一个只复制自己认得字段的适配器会让那道守卫**不可达**——它等于悄悄关掉了一个
   自己看不懂的安全检查。**翻译器转发不了的东西也必须转发，让对面去决定。**
   （这条有变异测试：白名单化 ⇒ `client_authority` 那条断言立刻红。）
3. **误判幂等。** 重发的 JSON-RPC 请求是同一次逻辑尝试，必须复用幂等键；
   但只看 `id` 会在客户端复用 id 时误撞。所以键 = `sha256(id ‖ 参数集)`：
   同 id 同参数去重，同 id 不同参数不去重。

## 与 DSH / Inimerse 的关系

**借契约，不借代码库。**

两个宿主各自有一个形态相近的权威层（DSH 的会话组织、Inimerse 的 Verse Layer），
它们的**协议形状值得吸收**（服务端分配序号、幂等键必填、拒绝是结构化返回值、
能力协商不静默降级、追加式哈希链日志）。但**不引入它们的进程、类型或生命周期**。

理由：把别人的抽象变成自己的地基，就是复制"依赖 DSH"那一类错误——
而这一次，那个别人**自己都在去 C 化、换类型系统**。

## 当前状态

`shell` 与 `mcp` 都已实现并有可跑的判据；适配器守卫在两个方向上都做过注入测试。
**没有 `adapters/dsh/`，这是刻意的。**

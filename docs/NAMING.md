## 四、结构性批评（比候选表本身更要紧）

### 1. 整张表按"动作"或"单一因子"取名，而宗旨是三个因子的**乘积**

宗旨：`万物 = AI × 算力 × Skill`，任一因子为零则积为零。

- **分诊台 / TriageDesk**：按动作取名。但**分诊与调度不在内核里** —— 它是
  `../organs/README.md` 里的仲裁器。内核只有四个概念 `Frame / Log / Budget / Refusal`，
  职责仅为完整性。建议书开篇说"它最核心的动作是分诊与调度"，那是**原 2946 行文档的框法**
  （L0–L3 升级 + 派发），写在分诊被移出内核**之前**。用旧架构的器官给整个系统命名，
  等于把旧架构冻进名字。
- **智巢 / 群脑 / 千脑**：只讲 AI（脑）。
- **百工 / 千手 / 匠网**：只讲 Skill。
- **巢 / 群**：只讲算力。

挑一个因子命名，就把**乘法讲成了加法**。

### 2. 带数字的名字与宗旨自相矛盾

宗旨「三生万物」的重点在**无限**（三 → 万物）。
百工 / 千脑 / 千手 / 百家把上限钉死在 100 / 1000 —— 这是从宗旨往后退一步。

### 3. 学名那一半不可用

DNSESC / LHMAES / DTES / SHIC / LCAM 五到六个字母，读不出来；
建议书自己在第二节就放弃了它们改用三字母码 —— **前后矛盾**。
「分布专家枢纽」中文不通（应为「分布式专家枢纽」）。

### 4. 产品名那一半**一个撞名都没查**

它给缩写做了冲突表，却给真正需要商标/域名查重的产品名零分析，
同时首推字面带 **Intel** 的 `IntelHive`。

### 5. DXN / Dexen 的具体问题

- `X` 是 e**X**pert 硬凑出来的。
- 「Dexen」读感接近药名（dex- 前缀）；DXN 亦是交易所代码。
- 其"无同领域重名"未经核查（见第三节）。

## 七、定案：TEPS（2026-10-11，项目所有者）

**TEPS = T·E·P·S = Tri-Experiential Praxis System。**

### 为什么它比「三生」和 `Texp` 都好

- **`Texp` 有一个我当时指出的自相矛盾**：它展开成 `Expert System`——MYCIN 式的
  「由人写好的规则库」，**恰恰是本项目论点反对的机制**。一个名字里含着一个它命名之物的
  否定式。**TEPS 没有这个词。**
- **`T` 保留 `tri-`**，也就是宗旨里唯一半被验收过的那一条：三个因子的乘积
  （没人写过的组合跑出了孩子都没有的行为）。
- **`Praxis`（实践）是承重词**：这个系统的核心主张是「靠做过而不是靠知道」，
  而 `Praxis` 正是「做」的那个词。

### 没有解决的一件事，必须写下来

**`TEPS` 是韩国一个有名的英语能力考试**（Test of English Proficiency）。
`web_search` 在本机**仍然不可用**（`HTTP 402 Insufficient Balance`），所以这一条的状态是
**未知**，不是**已清**。教育领域撞名通常不致命，但它是一个已知的、未核实的事实。

### 改名的实际成本（实测，不是估计）

`sansheng` 出现在 **90 处 / 52 个文件**（其中 45 个 Go 文件），加 `go.mod` 的一行
与目录名 `.sansheng/`。**没有任何大写变体**（`Sansheng` / `SANSHENG` 各 0 处），
所以替换是一次小写全替换。

⇒ 教训：**「改名成本是 O(1)」在 P0 时是真的，在 P4 时不再是。** 名字定得越晚，
它越是嵌进代码里——但这不构成「应该先定名字再开工」的理由，因为一个定错的名字
嵌得更深。正确的做法是**在它还是 O(1) 的时候知道它是暂定的**，并在每次变大时重新量一遍。

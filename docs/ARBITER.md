# capex 仲裁

**这一条来自项目所有人的一次驳回。** 在回答"三生万物"时我列的第二点是：

> 「capex/opex 混淆：现仲裁器 `U = P(success)×value − cost − latency` 是**纯 opex**。」

项目所有人回：**「改 ②」**。本文档是改的结果。

---

## 一、问题：纯 opex 的价值函数必然导致"永远临时应付"

```
U(action) = P(success) × value − cost − latency
```

这个式子里**没有"这件事以后还要做多少次"**。于是：

- 走 L3 解读一个意图：`cost` 高，但 `P(success)` 也高 —— **这一次这么算是对的**；
- 固化一个技能：`cost` 摊在这一**单次**决策上看，永远不划算。

**⇒ 每一次决策都局部正确，于是系统永远临时应付、永远不积累。**

**这不是参数没调好，是价值函数缺了一项。** 缺的这一项就是 capex。

---

## 二、改法：把 capex 变成显式项

```
固化(skill)  ⟺  V_fix > 0

V_fix = N_eff × (opex_now − opex_after)     ← 未来省下的运营成本（折现）
        − capex_fix                          ← 一次性投入
        − N̂ × P(毒化|E) × loss(毒化)         ← ★ 新增的负项
```

| 项 | 含义 | 从哪来 |
|---|---|---|
| `opex_now` | 现在每次调用要付多少（比如走 L3） | 审计日志里 `actual` 的均值 |
| `opex_after` | 固化后每次调用要付多少（≈0） | 内建原语或常驻脚本 |
| `N̂` | 预测的未来调用次数 | 历史频率 + 衰减，**保守取值** |
| `N_eff = Σ γ^i` | 有效折现次数（γ ≈ 0.95） | 未来调用不确定，要打折 |
| `capex_fix` | 固化这一次要花多少（捕获+验证+适配） | 工作量估计 |
| **`P(毒化|E)`** | **这个技能是错的却被固化了，概率多大** | **由证据等级决定** |
| `loss(毒化)` | 错了要赔多少 | 按任务类 |

---

## 三、那个负项是关键

> **固化一个错的技能，比不固化更糟。**

因为错误会被执行 `N̂` 次，**而且每一次都被记为"成功"**——除非核验器抓住它。
不固化只是慢；固化了是**快而错**，而且错得很隐蔽，因为它有"成功"的执行史背书。

### `P(毒化|E)` 由证据等级直接给出

| E | 含义 | P(毒化) | 后果 |
|---|---|---|---|
| **E1** | 沙箱执行成功一次 | 高 | 几乎不敢固化 |
| **E2** | 第二独立来源确认 | 中 | 谨慎固化 |
| **E3** | 外部权威 / 人类确认 | 低 | 放心固化 |
| **E4** | **反复成功 N 次无失败** | 极低 | 固化成本几乎只剩 capex |

### 这张表让整个阶梯闭合

**E4 不是人给的，是固化后观察出来的。** 于是：

```
固化 → 用 N 次 → 拿到 E4 → P(毒化) 下降 → 下一个技能更容易被判为值得固化
```

**这是一个正反馈闭环，而且它是合法的**——与"固化毒化循环"方向相反：

| | 毒化循环（要防的） | 这个闭环（要的） |
|---|---|---|
| 输入 | 模型生成的内容 | **真实执行历史** |
| 效果 | 错误被"证据化" | 固化门槛随实测下降 |

---

## 四、为什么它是外设（不是内核）

固化判定**跨越调用**：它不属于任何单次调用，而是一个周期性/触发式的判定。

```
输入：日志统计（调用频率、opex 均值、证据等级、成功率）
输出：{固化, 不固化, 观察}
```

**它是纯函数**：同样的输入给同样的输出，不需要唯一权威、不需要原子、不需要每次经过。

⇒ **纯函数不需要进内核**（判据见 [KERNEL.md](KERNEL.md)）。
所以 capex 仲裁落在 `organs/`，与 opex 仲裁放在一起。

**顺带一个收益**：仲裁策略可以整块替换、可以回放重算历史决策，而内核一行不动。

---

## 五、固化的两级阶梯

固化不是布尔量，是一段生命周期：

```
LLM 生成 / 抄来的代码
      ↓  第一次值得固化（V_fix > 0）
script       常驻解释器执行（Python 等），启动成本付一次
      ↓  调用次数 > N ∧ Beta 成功率 > 0.99 ∧ 启动成本占比 > 50%
code         编译产物（Go）
      ↓  通用到值得成为 ABI
内核原语      编进内核，成本 ≈ 0
```

**触发条件是三个，缺一不可。** 只看调用次数会把一个慢而对的技能编译成快的错东西；
只看成功率会让一个从没被调用过的技能被编译。

⚠️ 最后一级（升为内核原语）**必须经过 Gate 4 的词汇检查**：
一旦原语进了内核，它就不能再提"技能""策略"这类词——
**这自动限制了哪类东西够资格成为原语**（只有真正通用的机制够，领域概念不够）。

---

## 六、证伪点（可跑的测试）

这条设计**必须能被证伪**，否则它只是一段好看的公式：

> **人为让一个已固化的技能腐烂**（改掉它的下游依赖，或故意让它失败），
> 然后观察：调度器是否**自动**停止选它。

预期：Beta 后验随失败下降 ⇒ `P(success)` 掉下去 ⇒ `U(a)` 变负 ⇒ 该技能被弃用。
**没有人需要发现这件事。**

若调度器继续选它，则自校准机制是假的，本文档的第一节不成立。
